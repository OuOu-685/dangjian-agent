## ⚠️ 两处必须澄清的地方

### 1. 「输入 / 输出」不是「开始 / 结束」

面板上「输入」「输出」两个节点的**实际数据**是：

| 面板名 | type | 平台官方描述（原文） |
|---|---|---|
| 输入 | `"30"` | **支持中间过程的信息输入** |
| 输出 | `"13"` | **节点从"消息"更名为"输出"**，支持中间过程的消息输出，支持流式和非流式两种方式 |

所以它们**不是**「定义启动参数 / 返回最终结果」——那是**开始(`1`)/结束(`2`)** 的职责。
常见的错误说法是把「输入=开始、输出=结束」，那是**两个不同的东西**（详见 `02`）。

### 2. 「变量赋值」在不少资料里被归到别的分组

它属于**业务逻辑**类（与选择器/循环同级），不是数据库类。编号待实测。

## 补一个类型的最省事流程（30 秒 / 个）

1. 在那个工作流里 → 拖入一个该类型节点
2. **把输入参数配一下**（不配看不到字段结构）
3. 单击选中该节点 → `Ctrl+C`
4. 粘到记事本 → 存 `.txt` 发我（**一个节点就够**）

我拿到后会自动：读 `type` → 提字段骨架 → 写 builder → **往返测试比对** → 登记进 `TYPE_TABLE`。

## 判断类型的唯一权威

**`type` 编号**，其次 `nodeMeta.icon` 文件名。
**不要从文档目录里的名词反推类型** —— 目录里既有分组名也有节点名，会混。
