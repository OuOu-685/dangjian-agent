## 三、已证伪（网上流传但**是错的**）

逐条核实过，写在这里是为了避免被带偏。

| 错误说法 | 出处类型 | 实情 |
|---|---|---|
| 代码节点用 **Python 3.9**，通过 `get_input()` / `set_output()` 读写 | 二手教程 | 官方：**Python 3.11.3**，用 `params['名']`。`get_input`/`set_output` 这两个函数**不存在** |
| 代码节点默认超时 **8 秒**、要手动开 HTTP 插件才能联网、`requests` 的 `timeout` 必须 ≤5 秒 | 二手教程 | 官方：超时 **60s**；`requests_async` 内置无需开插件；没有 5 秒限制 |
| "**Coze 没有真正意义上的循环节点**，只能构建有限迭代的线性工作流" | 二手汇总 | 错。有循环节点（`type:"21"`），**且支持嵌套子节点**（顶层 `blocks` + 内层 `edges`），实测 3 个样本在用 |
| "剪贴板 JSON 就是官方导出格式" | 大量混淆 | 两套不同格式：剪贴板用数字 `type` + `blockID/name`；官方 DSL 用英文 `type` + `ref_node/path` |
| "节点编号就是 1 插件、2 大模型、3 代码、4 知识库…" | 二手汇总 | 那是**组件种类列举**，不是 `type` 字段值。实测 `type` 为 `1/2/3/4/5/6/8/15/21/32/42/43/46`，跳号严重 |
| "一个工作流可以按分支画多个结束节点" | 常见做法 | 官方硬约束：**只有 1 个开始 + 1 个结束**。输出定义挂在结束节点上，多结束 = 输出定义冲突 |
| "变量赋值节点用来做工作流内临时变量" | 常见误解 | 它操作的是**智能体变量**（跨会话持久化），不是工作流临时变量。要用"算个中间值"就该用**代码节点** |
| "代码节点里可以写多个函数、可以 `print` 调试" | 二手教程 | 官方：**不支持编写多个函数**；调试要用 IDE 的「运行」面板 |
| "结束节点可以自己算总数/拼接话术" | 常见做法 | 结束节点**不能做计算**。汇总必须在它之前用代码节点算好 |

## 四、不确定性怎么表达（交付时的写法）

遇到未证实项，**不要沉默地用掉**，也不要编一个数。按这个模板写在交付物里：

```
⚠️ 未证实：<字段名> 的取值
- 已知：在本项目里是 X（来源：实测样本）
- 未证实：是否还有别的取值
- 影响：若需要 Y，必须先实测
- 实测方法：画布上配一次 → 复制 → 读 JSON
```

例：

```
⚠️ 未证实：选择器"包含"操作符的 operator 值
- 已知：operator=1 表示"等于"（5 次实测）
- 未证实：样本里出现过一次 operator=7（字符串比较），疑似"包含"但无法确认
- 影响：若要用"包含"判断，填 7 有风险
- 实测方法：画布上配一个"包含"条件 → Ctrl+C → 粘到记事本看 operator
```

这既是技术诚实，也是**项目里"宁可说不知道也不编"这条铁律在元数据层面的体现**。
